1 / Знайомство

Проєкт «Створення гральних кубиків»

Тема уроку: випадкові числа, змінні та розгалуження. Перетворимо micro:bit на кубик для настільної гри.

Твоя місія · 15–20 хвилин

Після струшування отримай число від 1 до 6 та покажи його крапками на екрані 5×5. Навчися перевіряти всі гілки, не чекаючи випадковості.

Маршрут: 3 хв — теорія; 3 хв — дослідження; 7 хв — один варіант програми; 3 хв — перевірка з ШІ; 3 хв — квіз і підсумок. Інші редактори та ускладнення — за бажанням.

Потрібен браузер; плата необов’язкова для роботи з моделлю. Якщо використовуєш micro:bit, тримай його міцно й струшуй обережно, не кидай як справжній кубик.

Спочатку припусти

Якщо двічі випала шістка, чи обов’язково програма зламалася?

2 / Теорія

Як працює електронний кубик

Шість можливих результатів

Звичайний гральний кубик має шість граней із позначками 1–6. У моделі замість падіння кубика працює генератор псевдовипадкових чисел.

randint(1, 6) у MakeCode та random.randint(1, 6) у MicroPython включають обидві межі: можуть повернути і 1, і 6. Результати можуть повторюватися. Шість кидків не зобов’язані дати всі шість чисел.

Подія → змінна → гілка → екран

Подія — струшування. Змінна number зберігає одне число поточного кидка. Розгалуження вибирає один із шести малюнків.

Генеруй число один раз перед перевірками. Якщо викликати генератор у кожній умові, різні гілки перевірятимуть різні числа.

= записує значення, == порівнює. Після if, elif та else ставлять двокрапку; відступи позначають вкладені дії.

Два середовища Python

MakeCode Python використовує basic.show_leds та обробники подій. MicroPython у Python Editor використовує display.show(Image(...)) і цикл перевірки жесту. Це різні набори команд — приклади не можна змішувати.

Сьогодні працюємо з числом number, рядком "shake" і логічним результатом порівняння True або False.

3 / Дослідження

Від числа до малюнка

Прогноз перед запуском

Нехай number = 4. Перевірки 1, 2 і 3 хибні. Що станеться далі?

Блок-схема одного кидка

Після показу програма очікує наступного струшування. Гілка «інакше» відповідає шістці, бо число вже обмежено діапазоном 1–6.

1. Подія: струшування

Почни з події «Подія: струшування». У ромбі обери гілку «Так» або «Ні» за результатом перевірки. Зістав кроки схеми з умовою завдання: number ← випадкове ціле; 1–6; number = 1?; Показати 1 крапок; number = 2?; Показати 2 крапок.

Як читати блок-схему
  • Овал — початок або кінець.
  • Прямокутник — дія, обчислення або пауза.
  • Паралелограм — введення чи виведення даних.
  • Ромб — перевірка умови з виходами «Так» / «Ні».
  • Стрілки задають порядок; стрілка назад означає повторення.

Кінець обробки події не означає завершення всієї програми.

Алгоритм псевдомовою

Це опис звичайними словами, а не код для редактора. ← означає «записати значення». Відступи показують дії всередині події.

Робот: гральний кубик

Відтвори розгалуження уроку. number = 1 → Показати 1 крапок; number = 2 → Показати 2 крапок; number = 3 → Показати 3 крапок; number = 4 → Показати 4 крапок; number = 5 → Показати 5 крапок. Інакше → Показати 6 крапок.

Як працювати з грою · крок за кроком
  1. Прочитай правило уроку. Обери умову для кожної перевірки.
  2. Признач дію гілці «Так». «Ні» веде до наступної перевірки; після останньої — до «Інакше».
  3. Обери кінцеву дію «Інакше» та запусти робота.
  4. Простеж підсвічені кроки й результати тестів. Після помилки прочитай підказку, зміни налаштування та повтори.

Це один прохід розгалуження. Події, зчитування даних, паузи та повторення залишаються в програмі уроку; у грі налаштовуємо лише вибір дії.

Гра перевіряє наведені приклади, не читає датчики й не запускає реальне радіо. Зелений результат означає проходження цих тестів.

    Коротке ТЗ «Подвійний кубик»

    Мета: отримати два незалежні значення та їхню суму. Засоби: поточний редактор, кнопки A/B, змінні та додавання.

    Поведінка: A показує один кидок; B обирає два числа 1–6, показує перше, паузу 1 с, друге, паузу 1 с, а тоді їхню суму як число. Сума лежить у межах 2–12.

    Перевірка: підстав пари (1,1), (1,6), (6,6): очікуй 2, 7, 12. Поверни два окремі виклики генератора.

    Підказка: як виконати додаткове ТЗ

    Створи first і second, кожній змінній дай власне випадкове число. sum = first + second. Подвоєння одного числа дає лише парні суми й не моделює два кубики.

    Анімація кидка

    Завдання: перед фінальною гранню покажи п’ять коротких кадрів із паузою 200 мс. Після анімації покажи один остаточний результат. На micro:bit V2 за бажанням додай тихий короткий звук; для V1 потрібен зовнішній звуковий пристрій.

    Анімація додає ефект руху, але сама не робить генератор «чеснішим».

    Спочатку спробуй самостійно. Відкривай лише потрібну підказку.

    1. З чого почати?

    Працюй у копії проєкту. Почни лише з анімації без звуку.

    2. Які засоби допоможуть?

    П’ять повторень: показати кадр → пауза 200 мс. Після циклу — остаточний кидок.

    3. Як перевірити?

    Тривалість пауз разом 1000 мс. Фінальна грань не зникає сама. Перевір послідовність з підставленим результатом 6.

    Навчайся з ШІ: знайди помилку генератора

    Уяви програму, яка викликає випадкове число окремо в кожній умові. Попроси ШІ пояснити, чому це не перевірка одного кидка, і запропонувати тести. Перевір пораду самостійно в обраному редакторі.

    ШІ може галюцинувати: вигадати команду, переплутати редактори чи пообіцяти всі числа за шість кидків. Перевір код запуском, межі — довідкою, а кожну гілку — підставленими числами 1–6.

    Підказка: що таке промпт?

    Промпт — запит до ШІ. Назви редактор, мету, свою спробу та потрібну допомогу. Попроси пояснення й тести, не передавай особисті дані.

    Генератор промпту · сформулюй власне запитання

    Ця форма лише складає текст, а не звертається до ШІ. Скопіюй результат у дозволений учителем інструмент.
